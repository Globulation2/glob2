## Recommendations

1. **P2 correctness — require current-platform golden coverage.** `test/MapGeneratorGoldenTest.cpp:191` aggregates the maximum revision across all platforms, but lines 224–225 skip local rows with another revision. A current macOS row therefore prevents a stale Linux row from being reported; `--require-rows` only checks whether *any* platform rows exist. The checked-in table has eight old-revision Linux rows for each of methods 59, 63, 64, 65, and 69, alongside twelve current-revision macOS rows each. Linux consequently skips all five affected generators and can report success. Track/report current-platform revisions separately, and require current-revision coverage for every registered generator when `--require-rows` is requested. Regenerate foreign-platform rows from actual binaries. Add a small regression for a table containing fresh foreign rows plus stale/missing local rows; it must fail clearly. Do not make absent coverage look verified.

2. **P2 correctness — remove the image-import twelve-team ceiling.** `src/MapImage.cpp:652–654` rejects more than twelve colony markers. `exportMapImage` immediately above it exports every live team, so newly supported 13–16-team maps cannot round-trip through the canonical image interchange. Use `Team::MAX_COUNT` in the bound and diagnostic, update `docs/map-generators/CLI.md:245`, and extend `test/test_map_image.py` with a sixteen-marker import/export/reimport plus seventeen-marker rejection. Space markers sufficiently far apart to distinguish team-capacity failures from colony-footprint failures.

3. **P2 validation — exercise migrated Maxima behavior, not just immediate game checksums.** `test/TeamLimitTest.cpp:230–239` compares immediate checksum vectors for a retained v126 Maxima save and its v127 reload. However, `src/Player.cpp:188–200` hashes only BasePlayer fields, not the AI director. The test's “every simulation field” comment overstates its guarantee, and a lost opponent/campaign decision could pass. Compare the director's serialized state and run paired subsequent AI decisions/orders plus simulation steps from the migrated and reloaded state, retaining per-tick checksum evidence. An existing continuation harness is preferable to a duplicate scheduler. Ensure RNG ownership is restored separately for the two branches. Also add targeted malformed/undersized script-generation team-slot probes so the newly introduced serialized count's bounds are exercised rather than inferred from the happy path.

4. **P3 comments/documentation — correct the Warrush behavior claim.** `src/ai/AIWarrushTuning.h:39–40`, `src/Version.h:10–11`, and `docs/development/reference.md:328–330` claim that the longer bootstrap window changes the opening in smaller matches. In `src/ai/AIWarrush.cpp:307–312`, extra probes see null teams and fall through to the same ordinary decision logic without a return or RNG draw. Existing <=12-team matches therefore do not acquire a timing delay from this change. Describe the additional probes for newly supported team slots accurately; add a paired <=12-team order/checksum regression if making a preservation claim. Keep version gates justified by enlarged state/checksum and client-capacity boundaries rather than the unsupported smaller-match timing rationale. Also correct `docs/map-generators/CLI.md:24`, which still advertises Encircled Kingdom as 3–12 colonies.

5. **P3 maintainability — derive alliance-dialog storage from the live player cap.** `src/gui/GameGUIDialog.h:113–114` stores per-player settings and team indices in literal-16 arrays. These now exactly match the engine cap but will silently become undersized on a later increase. Use `Team::MAX_COUNT` for these live controller arrays, with the appropriate dependency already available through the GUI header chain or an explicit include. Preserve intentionally fixed wire/mask widths elsewhere. Validate opening/changing alliance or chat controls for controller 15; compile-time capacity alignment is the main purpose of this cleanup.
