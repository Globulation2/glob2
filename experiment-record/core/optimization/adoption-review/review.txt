Independent simplicity/adoption review — provisional pending mature96 + V2/replication timings

Scope: read-only production FIRST3 V1 plus isolated snapshot-V2 and telemetry-V2 source/patches. No builds/games/profiles/production edits. This is an adoption decision framework, not new measured evidence. Existing focused and initial/mature conformance establish tested arithmetic/wire/lease behavior for each factor; they do not establish the eventual integrated source or every native platform.

1. Keep affinity-aware worker auto-sizing as the minimal leading optimization.
The change has a general invariant: auto participants cannot exceed available logical CPUs on Linux/Android, while existing explicit counts, pure injected policy, serial fallback and browser cap remain. OS discovery is isolated in a small implementation file. It does not assume 3 physical cores, SMT topology, quotas or universal optimal count. The observed restricted-affinity wins support fixing oversubscription, not hardcoding a preferred benchmark count or claiming unrestricted-host benefit. Do not add scheduler V2 or topology heuristics to the final patch on the current evidence.

2. Prefer telemetry V2 over shipping V1 if the remaining timings remove the credible large-mixed regression.
V1 descriptor interning meaningfully reduces repeated metadata; its extra tree comparisons are a demonstrated CPU tradeoff. V2 is a readable small refinement: a nullable pointer to prior-current immutable SchemaPtr, exact ordered ranges::equal, existing lookup fallback, one current.find. No new persistent cache/state, unchecked hash, separate fast-path schema order, or wire format. The pointer is valid throughout schemaFor because current is not mutated until capture acceptance. Duplicate players still compare against prior accepted capture, not latest rows assembled in the same capture. Field position, duplicate descriptors, embedded NULs, values, stamps, rejected/truncated frame retention and copied-stream lifetime remain covered by focused tests.
The extra equality before set lookup can slow genuinely changing schemas, and retainSchemas still inserts canonical pointers per accepted frame. Thus V2 remains conditional on holdout/mixed and mature CPU+wall evidence, including per-layout distributions rather than pooled aggregate. If V2 keeps a credible CPU regression, keep the original representation and reconsider a separate representation change later; do not ship known V1 regression solely because pooled CPU is flat. Avoid broad restructuring or more caches before results.

3. Treat snapshot ownership as optional; V2 is mechanically cleaner only if it earns a useful gain.
V1 sweeps every unleased descriptor at each resource-field capture, including unchanged-generation captures. V2 makes reclamation demand-driven: normal descriptor reuse, tryAcquire existing planes, at most one idle-descriptor sweep after actual pressure, then ordinary acquire. It preserves capacities and existing strong-lease/acquire-fence lifetime contract. It is a generic allocation-pressure policy rather than a map/thread heuristic, but it adds a nullable pool API plus caller state/branching and still scans twice after a failed pre-reclaim probe. If mature/V2 timings show no useful CPU or retained-capacity improvement, remove BOTH ownership variants from final integration. Flat timing alone need not prohibit a clearly measured memory reduction, but require that reduction from native RSS/capacity evidence, not an inferred cleanup story. No need to ship unconditional V1 because its source is already in main.

Diagnostics can remain independently if ownership is removed.
ResourcePlaneMemoryMetrics, Store forwarding and snapshot-memory.json export under existing --telemetry gradient-stats do not require discardUnused or tryAcquire. Keep count/capacity/leased-descriptor interpretation explicit: direct plane leases include idle descriptors, vector capacity excludes allocator/control-block overhead, result export is a single stage, not peak memory/RSS. Generation copy/reuse counters do add bounded per-plane increments even without diagnostics; retain only if useful maintained telemetry, and do not call them zero-hot-path work. A query-only census can survive without those counters if an intentionally smaller diagnostic API is chosen, but would require its own updated tests/documentation/evidence rather than relabelling old measurements.
Minimal rollback ownership path: remove BufferPool::discardUnused (and V2 tryAcquire), remove only the WorldCapture sweep/reclaim branch; restore original acquisition. Retain optional census/read/export + its neutral tests. Remove or rewrite tests whose assertions require reclaimed descriptors, leaving unchanged-field reuse, immutable old/worker-held observations and direct plane-lease census tests. CLI/docs should describe actual retained diagnostic output, not obsolete cleanup guarantees.
The new BuildingGradientSearch queue/pool census APIs are independent, but are currently not consumed by the new snapshot-memory.json export. If there is no maintained diagnostic caller, omit this extra unexported API from the optimization patch or split it into a narrowly justified diagnostics follow-up. It is not required for worker/telemetry adoption or resource-plane sidecar. Do not remove existing search behavior/features.

4. Scheduler V1 remains isolated and low priority.
Near-flat preferred-count evidence does not justify a fourth production policy or a bounded-V2 notification extension. Auto-sizing addresses the large unnecessary participant count directly. Keep all existing worker/service/presentation notifications and liveness policies in the final baseline unless actual mature benefit outweighs workload-dependent tradeoffs and full additional liveness/browser gates.

Minimal integration options after remaining results:
A) Worker only + optional resource-plane diagnostic sidecar: lowest behavioral/lifetime risk, no ownership scheduling changes or replay representation changes.
B) Worker + telemetry V2 + optional census: likely smallest worthwhile CPU/memory package if mixed/holdout/mature telemetry gates pass. Replace main V1 hint lookup with already-tested exact isolated V2 diff and added focused test; do not stack a fresh optimization.
C) Add snapshot V2 only if mature/holdout metrics demonstrate a useful independent benefit. Replace V1 eager sweep with exact isolated V2 diff. Do not combine unmeasured cleanup thresholds, pool-size caps or alternative representations.
For any path, retain existing feature behavior and version/wire formats. No simulation revision bump is expected when final equivalent arithmetic is verified; any actual trace divergence must block adoption rather than be accepted as a performance tradeoff.
