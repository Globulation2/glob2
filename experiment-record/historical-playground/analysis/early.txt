---------------------------
The six experiment intervals contain 653 reachable integrated commits and 180
first-parent commits: Sep 5 492/19, Sep 8 30/30, Sep 11 25/25, Sep 14 36/36,
Sep 17 42/42, Sep 20 28/28. The first sample interval integrates a long-lived

small engine changes. early-inventory.json records every full SHA, commit body,

about efficient implementations, caches, defaults and diagnostics; reverting
pathfinding, diagonal timing, job swaps or starvation fixes is not recommended.

Ranked CODE CANDIDATES, not causal conclusions:

A. BFS -> repeated raster chamfer sweeps. 1e228ce06 introduces the alternative,
7ff6e3a1c makes it production, a518d7087 removes BFS, 487027aff simplifies the
kernel. The Sep 5 MapGradientGlobal.cpp performs forward/backward full-map
passes until no cell changes. Its own comment says obstacles and torus bends
require multiple passes (~K/2 direction changes); it caps at 256 passes. This
can increase total visits relative to the original queue, especially as colonies
add obstacles. There is no retained same-field performance benchmark showing
this caused the current 2x cost. It is the highest-value kernel ablation.

B. Stable hiring order and Nicowar behavior. 419eb4bd4 adds gid as final building
sort tiebreak: previous ties were implementation-dependent, consumed RNG in a
different order, and produced a different end state. d36382e9a wraps Echo gradient
external coordinate queries used by Nicowar farming; the old edge reads accessed
wrong-row or uninitialized memory. c1797f53e zero-initializes strategy state.
These fixes can change population/colony placement and computational work.
More game ticks do not explain doubled CPU per tick by themselves; matched
unit/building/field-count windows are necessary. Preserve these correctness fixes.

C. Broad TU splitting and C++ modernization may change inlining/code layout.
This is a weaker hypothesis without retired-instruction/call attribution. Build
logs should be compared before invoking it; baseline and later binaries use the
same GCC 13 release setup, with explicitly documented adapter changes. Do not
blame 'modern C++' or code organization from temporal coincidence.

Changes expected to HELP, not convincing slowdown explanations:
- 46a6a2d3d repairs a Nicowar explorer-attack scratch leak: 1024 pointers (~8 KB)
  per call, historically ~90 calls/game, scaling with AI count. Replay equality
  is reported. Flat aggregate RSS does not negate the fix amid other changes.
- Static type tables replace startup file loading (5ee9a56bf/9211f3757/
  94a974e3c/79e738918).
- Dead logFile/fprintf infrastructure removed from game/team/unit/building/AI
  (612125b09/18a8377f3/756537860/d77ce64c9/cca806bd2).
- New Cortex policy/training tooling is not the selected AI in this workload.

Recommended diagnostic sequence: compare immediate parent/merge of #129 with
all other inputs equal; then the chamfer transition commits. Clone actual
Playground gradient inputs, compare BFS with corrected seed handling against
chamfer, count visits/passes, CPU and field calls. Keep stable order, torus query
fix and all new gameplay semantics identical in the final optimized version.

2. Sep 05 -> Sep 08: weighted fields improved throughput at a memory cost
----------------------------------------------------------------------

classes, lazily built with bucket-queue Dijkstra. Building full-map fields replace
32x32 local grids and 5x5 minigrad. f80d0ef50 matches movement timing to octile
costs: diagonal speed is divided by sqrt(2), removing the old 41% diagonal speed
advantage. These are intentional game pacing/route changes, not pure optimization.
https://github.com/Globulation2/glob2/pull/184

peak RSS 140 -> 179 MB. At matched unit counts in 512-tick windows, Mazury
128x128 two teams improved TPS 11-41%; a tiny 64x64 two-team map at 30/50 units
regressed 14%/6%, becoming ~flat at 80 units. These observations demonstrate
workload sensitivity, not a universal gain. Five-seed 15000-tick Mazury economy
changed 72.1 -> 61.4 -> 59.5 units/team for old, old+diagonal fix, new respectively.

9e8b378eb optimized wrapped neighbors, terrain costs and queue destinations.
Original Apple M3 / Apple Clang -O3, median three alternating paired serial
15000-tick runs: core CPU G2 2.870 -> 2.176 s (-24.2%), Playground eight Numbi
3.327 -> 2.580 (-22.5%), Archipelago 2.989 -> 2.204 (-26.3%), BigArena256
15.269 -> 11.139 (-27%). Whole-process elapsed fell 17-20%; core timer excluded

Feature benefit: 48 scenarios (8 maps, 3 AI mixes, 2 seeds), round-trip alone
median unit/building growth 0% at checkpoints; stacked swaps +6.7/+7.6% units

buildings, stacked +13.8/+12.5%. Human-paced four AINone Petri colonies show
round-trip +12% deliveries on one saturated 108-worker island, and larger gains
with swaps. Preserve feature: optimize repeated field construction/scoring,
not remove better routes or task exchange. Population gains themselves create
more computational work.

Current interval CPU/tick +93.1%, RSS +8.47 MiB. These features are plausible
contributors, but historical 13-18% does not account for the whole measured
93% delta. Autosave serialization amplification matters: every 256 ticks earlier
headless code serializes all cached fields. Profile solver, hire comparisons,
field counts/bytes and autosave serialization separately. Other changes include
unit survival on building destruction, trapped-colony elimination, stats/save
continuity and presentation/menu assets. Those are not automatically cost-free,
but menu/render changes should not be blamed for recurring headless CPU without
execution evidence.

Priority core optimization investigations (preserving features)
--------------------------------------------------------------
1. Exact-field gradient kernel and allocation/rebuild accounting across all sizes.
2. Better cache lifetime/refresh/repair with deterministic publication and saved
   continuation semantics; record builds, cache hits, bytes and cause separately.
3. Job/hiring scoring: prove it reads caches without allocation/refresh; efficient
   stable eligible lists/budgets only if gameplay quality retained and measured.
4. Diagnostic implementation: default-disabled performance timing, bounded/compressed
   stat history and compact overlap counters if their required range permits.
5. Maintain default autosave-off for headless; report old-policy costs separately.
6. Separate whole-game E2E, fixed-tick sim CPU, unit/building-normalized windows and
   field-kernel microbenchmarks; preserve determinism/save/replay compatibility.
