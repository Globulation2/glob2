Changes in rules, random streams and AI can change game length and workload. End-to-end savings alone do not isolate engine optimization; inspect tick counts and CPU per tick together. These measurements cover Linux x86-64 on one host with GCC 13, release builds and four disjoint groups of three physical cores plus their SMT siblings. Build elapsed time

Oazis reuses the same prebuilt binaries as Playground, so this is shared preparation evidence rather than a second build benchmark. Bars show recorded final successful SCons invocation times and logged compiler commands. Job counts, cache states and resumed work differ. The earliest two invocations logged no compiler commands and were up-to-date checks. Compiler CPU and original cache-hit counts are unavailable. Asset export is a serial graph action. Multiplying elapsed time by requested jobs cannot normalize these measurements; no ideal-scaling curve is plotted. Detailed audit and shared build-times.csv.
