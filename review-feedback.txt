Independent review of music resilience changes

Reviewers: native/producer reviewer and browser/coverage reviewer (two sub-agents).
All confirmed findings were addressed in the working tree.

Correctness findings and fixes:
- Preview pause discarded decoder-ahead PCM. Both consumers retain queued samples
  and their partial-block cursor. Native output ramps around pause; the browser
  resumes the exact next prepared sample. Consumer position drives the display.
- Preview controls could wait through a native refill. They now wake the worker
  and interrupt refills between bounded blocks.
- Browser reset used decoder-ahead position. A generation-checked worklet reply
  supplies the consumed position. A one-second timeout releases the command
  credit and restores pause state without guessing a seek position.
- Intentional browser hide/show refill inflated starvation. Intentional silence
  no longer counts as an underrun.
- Repeated paused seek/reset could replay a retained pre-pause sample tail.
  Both consumers clear that tail after entering silence. A waveform-sign test
  covers repeated browser generations with both transports.
- Root integration review found missing music files in static release packaging.
  Worker, worklet, Wasm loader/module, references and Opus notices now ship
  together with versioning, hashes and gzip validation. The browser reviewer
  independently checked the packaging fix and found no additional blockers.

Architecture and readability:
- New MusicTypes.h separates value-only playback contracts from decoder and
  queue implementation headers; SoundMixer documents owner-thread/lifetime rules.
- Producer removes legacy self-pointers/macros and shares replacement commit
  logic. Compressed bytes have unique ownership; original authorship is retained.
- Browser audio code is formatted, control/shared indices named, and ring
  publication/acknowledgement invariants documented.
- Existing development/browser/test docs describe ownership, pause/reset,
  buffer credits, deployment dependencies, diagnostics and validation limits.
- The stress harness has bounded sampling, finite-duration validation, failure
  reporting for competing workers and guaranteed browser/worker teardown.

Qualification limits:

or native Windows/macOS/mobile device qualification. Queue/sanitizer tests cannot
establish hardware output continuity. No simulation/save code or version changed.
