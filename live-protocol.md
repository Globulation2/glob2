# Live-match experiment protocol

Frozen release sources: before 3a3917757752fe64a2af9c1dc964c074794ebf3e; compact after 5a40f7a9f281cd1aa71c6980573cee3f6f35a36f. Identical Linux-only diagnostic program modifications; GNU linker wrap observes the authoritative simulationStep on its owning thread, not scene publication. All canonical state access stays on the owner or before startup/after join. No shipping code changes. Existing movement behavior remains serial/reference; planned movement is not enabled.

One excluded full warmup pair then ten paired repetitions. Alternate before/after order by repetition and case. Fresh process and fresh match state each run, unique user directory. No outcome-based extension or pruning. Each normal-speed run has 3 seconds warmup then 15 seconds measurement; 30 TPS nominal, drawing capped at 60 FPS or explicitly unpaced. Max simulation speed uses the existing preset 10, renders at 60 FPS, warms 128 ticks then measures exactly 1024 ticks. Report TPS using owner completion timestamps at fixed-tick boundaries; UI/CPU/FPS windows can differ by one pacing interval. Match histories and populations recorded independently; max-speed common tick sequence required.

Workloads: 32-worker ordinary control; 1024-worker fixed-order colony at normal/uncapped rendering/max simulation speed; same 1024-worker colony with Cortex controller at normal speed. Cortex fixture created using the existing player/header initialization and full GUI save format, loaded unchanged by both variants. Fixed and evolving orders kept separate. No input orders from a human, single team, no combat. The short colony fixture is not yet qualified for sustainable long-run gameplay.

Presentation: actual Engine threadedClientFrame + drawSession + SDL software draw/present on an X11 Xvfb server, visible window 640x480. Capture only at normal production read boundaries; no forced per-frame capture. Clouds off, audio muted, compute participants 4. UI frame pacing is the only render cap. Presentation remains in measured draw time. No claim about GPU/desktop compositor or hardware display FPS.

Exclusive balanced cgroup-v2 partition reserves physical cores 4-7 and SMT siblings 20-23. Runner/game/Xvfb affinity 4-7. A library helper widens its inherited affinity to the reserved partition; the runner restricts only its own newly created game threads back to 4-7 during startup and audits the result. Other cgroups cannot schedule on the reserved physical cores. Governor schedutil and boost disabled remain unchanged. Record kernel/topology/frequency, all process-thread affinity/cgroup checks, partition validity and cleanup restoration. Shared cache/memory/power/interrupt effects remain possible.

Primary outcomes: colony normal process CPU per measured wall second; colony uncapped achieved FPS; colony max-speed achieved TPS. Paired geometric mean ratios and run-level bootstrap confidence intervals (100000 resamples, seeded); 95% pointwise and 98.333% family-adjusted across these three primary outcomes. All other outcomes exploratory with 95% intervals. Frame samples within a run are not independent repetitions. Report both before/after means, missed-frame counts, p95/p99 draw/present and tick wall/CPU, scene age, capture copied bytes and capture time. Capture counters are collected per measured advancing simulation step, excluding warmup; separately retain whole-session counters. Capture is owner work, not part of every GUI draw frame.

Correctness tracing separate from timing: heavy per-tick simulation checksum on owner, compare common authoritative tick prefix across variants at every scenario; unequal final ticks from wall pacing are not mismatches. Compare max-speed exact measured tick ranges. Timing does not compute checksums. Existing core representation equivalence/replay/save tests remain separate evidence.

Post-run counter interpretation clarification: legacy bytesCopied includes logical populated unit-record payload, not only authoritative memcpy state bytes. Report this as logical capture payload; separately show state-copy and record sizes. No commands, repetitions or primary outcomes changed. Native threaded presentation is independently paced; preset 10's serial interval value16 is recorded as a setting, not claimed as actual threaded capture cadence.
