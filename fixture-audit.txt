performed on 2026-10-13. No builds, simulation tests, or fixture edits were run

seeded-compositions-units.trace
------------------------------
Both traces contain 150 rows: three seeds, each with ticks 0 through 49.
Seeds are 410362371, 1274675741, and 2956435871.
Every seed, tick, and RNG-state SHA256 digest is unchanged.
Only the full simulation checksum column changes, in all 150 rows.
For every row, old_checksum XOR new_checksum == 4194304 == 0x00400000.

The XOR matches the header-only change exactly. MapHeader::checkSum mixes
VERSION_MINOR; changing 160 to 161 changes its least significant input bit,
which the header rotation moves to bit 31. This fixture has one team and one
player. Game::checkSum applies nine subsequent one-bit right rotations to the
header contribution, moving that difference to bit 22 (0x00400000).
The checksum function's other XOR inputs do not amplify the header delta.

Interpretation and limitation
-----------------------------
The regenerated G2MR is a fresh current-version golden with the same scenario
and seed, but a different human order stream. It must not be presented as
same-orders before/after evidence for the service-restoration fix.

The unchanged TurnEngineHarness uses std::uniform_real_distribution and
std::uniform_int_distribution, and has multiple RNG calls among function
arguments. A seed alone therefore does not guarantee the same fixture order
stream across toolchains. The old fixture's regeneration toolchain and the
specific cause of these order differences were not established by this audit.

The intended compute-thread comparison uses the exact same new G2MR record
for both CLI runs (one and four workers). That comparison is separate from
this structural fixture audit; its results are recorded in the CLI evidence.
